Browser storage and WebGPU buffer measurements — issue #169 milestone 2

Issue #169 milestone 0 already proved that ONNX Runtime Web will multiply against a WebGPU buffer this project owns, and will reread that buffer after it is overwritten. Milestone 1 measured that Qwen3-30B-A3B keeps only 0.81 gigabytes resident and can stream the other 15.19 gigabytes. This page measures everything underneath both of those:

  • how many bytes this origin is allowed to keep on disk, and whether the browser promises not to delete them;
  • how fast one expert-sized block of 2.53 megabytes comes off disk through the Origin Private File System and into a WebGPU buffer;
  • whether that write overlaps a compute pass or waits behind it on the single WebGPU queue;
  • and how much WebGPU buffer memory one Chrome page can hold at once before allocation fails.

No model is downloaded and ONNX Runtime Web is never loaded. The page writes a test file of about 1.27 gigabytes into the Origin Private File System, reads it back, and removes it again at the end of the run.

Persistence is granted differently to an ordinary tab and to an installed Progressive Web Application, so run this page twice: once in a tab, and once after installing it from the address bar.

The allocation ceiling probe is behind its own button on purpose. It deliberately takes WebGPU buffer memory until the device refuses, and a device pushed that far can be lost, which takes the tab with it. Run the measurements first, read them, and only then press the second button.
