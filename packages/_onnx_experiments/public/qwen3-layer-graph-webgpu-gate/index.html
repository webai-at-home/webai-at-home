The Qwen3-30B-A3B layer graph on WebGPU — issue #169 milestone 6

Milestone 6 of issue #169 ran Qwen3-30B-A3B in the browser and it produced words that are not words. The same graphs and the same expert blocks produce sensible text outside the browser, so the fault is in something the browser does that the processor does not.

gate_qwen3_moe_non_expert_graph.py already checked the Qwen3-30B-A3B layer graph against the reference implementation, and it matched to 7.875e-06. But it checked it on the processor. Nothing has ever checked that same graph on WebGPU, and Qwen3-30B-A3B is the first graph in this project with grouped-query attention — 32 query heads reading 4 key and value heads, built out of Unsqueeze, eight Concat copies and a Reshape.

So this page runs one layer graph twice, on the same inputs: once on the processor, through the WebAssembly execution provider, and once on WebGPU. Both are running the same file, at single precision, so they should agree to rounding.

OLMoE-1B-7B-0924 is the control. Milestone 5 generated correct text with its graphs on WebGPU, three times over, so whatever the two execution providers disagree by on that graph is what ordinary rounding looks like here. There is no tolerance written down by hand: the control measures the scale, and Qwen3-30B-A3B has to sit near it.
