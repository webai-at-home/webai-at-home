The expert residency layer — issue #169 milestone 4

Issue #169 milestone 3 published Qwen3-30B-A3B as 6144 expert blocks of 2,727,936 bytes each, 15.61 gigabytes in total, at a pinned revision. This page is the layer that decides which of those experts are in graphics memory at any moment, and measures what that decision costs. It is the part of this work that no framework provides.

  • the blocks are written into the Origin Private File System, with the persistence grant requested;
  • a fixed ring of staging buffers is created once and recycled, never one for each step;
  • an expert is read from disk straight into a mapped buffer and moved with copyBufferToBuffer, never through queue.writeBuffer, which milestone 2 measured at about thirty times the queue cost;
  • the cache is given its graphics memory budget as a number, because milestone 2 measured that WebGPU never refuses an allocation and so a layer cannot discover its own budget;
  • and the run records the cache hit rate, the time stalled waiting for weights, and the time for each step.

The expert selection driving the loop is synthetic. The real sequence comes from the router of Qwen3-30B-A3B reading a real prompt, which needs the graph milestone 5 builds. Two sequences are run instead: a uniform one, which is the worst case any cache can meet, and a skewed one. Every hit rate below must be quoted with the sequence that produced it, and neither is Qwen3-30B-A3B.

Filling the store downloads real bytes from Hugging Face and keeps them. It is resumable: only blocks that are missing are fetched, so pressing the button again after closing the page costs nothing for what already arrived. Persistence is granted differently to an ordinary tab and to an installed Progressive Web Application, so this page carries a manifest and can be installed from the address bar.
