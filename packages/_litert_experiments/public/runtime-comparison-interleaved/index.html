Both runtimes in one page, alternating

Milestone six of issue #179, done a second time and properly. The separate pages could not be compared with each other: the same page, with the same settings, gave anything from 7 to 25 tokens per second on different loads, so a number taken from one page and a number taken from another say nothing about the two runtimes.

This page loads both runtimes and runs them in alternating blocks. Whatever makes the machine fast or slow at a given moment — how warm it is, what the browser has cached, what else is running — now moves both columns together instead of one of them, and the ratio between them survives it.

What is compared is one decoder layer, decoding one token. LiteRT.js runs decoder_00-03, four decoder layers, with its key/value cache staying on the graphics processor. ONNX Runtime Web runs all three of its shards, and the figure is taken from shard 2, the only one that is nothing but decoder layers — shard 1 also carries the token embedding and shard 3 the final normalization and the language-model head.

Both are checked against the same PyTorch reference while they run. Remember what they hold: ONNX Runtime Web has four-bit weights and a fused attention operation, LiteRT.js has 32-bit floating point and attention built out of separate operations. See the first comparison page for the whole of that difference.
