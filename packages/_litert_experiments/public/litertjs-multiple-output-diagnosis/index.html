LiteRT.js multiple output diagnosis

Part of milestone one of issue #179. The key/value cache residency gate found that a shard-shaped graph produces wrong numbers on WebGPU and correct numbers on WebAssembly, identically for cache ranks 3, 4, and 5 and for cache sizes from half a megabyte to 42 megabytes. Neither the rank nor the size is the trigger.

These four graphs differ by one property at a time, so that the trigger can be named rather than guessed:

  • one_output_hidden_only — one output. The control, already correct on WebGPU.
  • one_output_cache_only — one output, updated by a value derived from the hidden state but never returned.
  • two_outputs_independent — two outputs, with nothing both returned and consumed.
  • two_outputs_shared — two outputs, and the hidden state is both returned and consumed. The reproduction case.

The graphs are generated artifacts and are not committed. Write them first with tools/cache_residency_export/export_multiple_output_diagnosis.py.
