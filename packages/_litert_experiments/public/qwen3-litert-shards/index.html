Qwen3-0.6B LiteRT.js shards

Milestone two of issue #179. Qwen3-0.6B split into ten independently loadable .tflite graphs: seven decoder shards of four layers each, and three language-model head chunks, one vocabulary slice each. The token embedding table is not a graph at all — it is a raw binary, and the one row a token needs is read out of it with an HTTP range request.

Every graph is loaded on its own, run once, compared element by element against the output PyTorch produced for the exact same input, and freed again. Then the whole model is chained: the embedding row, the seven decoder shards in sequence passing only the hidden state, and the three head chunks whose logits concatenate. The chained logits are compared against PyTorch running this same decomposition under the same conditions.

Each graph is loaded and freed one at a time, because the WebAssembly heap is shared by every loaded graph, and because one worker owns one shard in the real architecture anyway.

The graphs and the embedding binary are generated artifacts totalling about 2.4 gigabytes, and are not committed. Write them first with tools/qwen3_litert_shard_export/export_qwen3_shards.py.
