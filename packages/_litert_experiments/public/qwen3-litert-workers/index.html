Qwen3-0.6B across browser workers

Milestone four of issue #179. Qwen3-0.6B generating tokens with its shards spread across separate browser pages. Each page holds its own graphs and its own key/value caches, and only the hidden state crosses between them — 4096 bytes per hop, over a WebSocket relay in the development server.

The caches never leave the page that owns them, and never leave the graphics processor. That is the property this milestone exists to demonstrate, and the reason the architecture is worth having.

Generation is real: the conductor knows the prompt and nothing else, and every token after the prompt is the token the pipeline itself produced. The resulting sequence is compared against PyTorch.

Open one page per worker

  1. decoder_worker_00-11 — decoder layers 0 to 11
  2. decoder_worker_12-19 — decoder layers 12 to 19
  3. decoder_worker_20-27 — decoder layers 20 to 27
  4. head_worker — the three language-model head chunks, and the token choice

Each page loads its own graphs as soon as it opens, then reports here. The button turns on once all four have.
