The comparison against ONNX Runtime Web

Milestone six of issue #179. This page runs the three ONNX shards of Qwen3-0.6B that packages/_onnx_experiments already uses, on the same prompt and against the same PyTorch reference as milestones four and five, so that the two runtimes can be put in one table.

The two sides do not hold the same weights. Issue #179 says the comparison changes only the runtime. It does not. The ONNX shards are cut from model_q4f16.onnx: four-bit weights, sixteen-bit floating point everywhere else, and one fused GroupQueryAttention operation for each decoder layer. The LiteRT.js graphs are thirty-two-bit floating point throughout, with attention built out of separate operations. The first section of the output below reads that difference off the running sessions rather than asserting it, because everything else on this page has to be read in the light of it.

Setting What it selects
?cacheLocation=cpu The default. Every key/value cache is copied out to JavaScript on every call and passed back in, which is what packages/_onnx_experiments and the cluster do today.
?cacheLocation=gpu-buffer Every key/value cache stays on the graphics processor between calls, which is what milestone four does with LiteRT.js. Only the hidden state is read back.
?executionProvider=webgpu The default. wasm runs the same graphs on the central processor instead.
