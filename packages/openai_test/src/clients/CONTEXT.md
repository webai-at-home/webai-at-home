# Directory Context: `/packages/openai_test/src/clients`

## Purpose

The ways this package reaches an OpenAI-compatible endpoint, and the timing of every request it sends.

## Key Exports & Entry Points

- `completion_sender.ts`: `CompletionSender`, which sends one chat completion request through the `openai` npm package, measures when its first and last character arrived, and checks that the endpoint answered as the model that was requested.

## Rules

- There are exactly two clients and no third way to reach an endpoint. `raw_http_client.ts` is used wherever the wire itself is the subject — the server-sent event framing, the `[DONE]` terminator, the response headers, the error bodies, the model listing. `openai_package_client.ts` and `CompletionSender` are used everywhere else.
- Outside `raw_http_client.ts`, nothing builds a request body, parses a server-sent event, or reads a response body by hand.
- Retries are off. A retried request would be timed as though it were the first one, which would make every measurement this package produces untrustworthy.
- Every answer's own `model` field is checked against the model identifier that was requested, and a mismatch fails the request. This is the only thing that catches an endpoint answering as a model nobody asked for, since such an endpoint reports no error of its own.

## Background

- The two-client rule settles a contradiction between the two packages this one merges: one ruled that the `openai` npm package is the single transport, the other that a raw client must exist because some tests read what actually arrives on the wire. See [issue #208](https://github.com/webai-at-home/webai-at-home/issues/208).
- The reported model identifier check comes from Milestone 0 of that issue: LM Studio 0.4.20 answers a request naming a model it cannot serve with HTTP 200 generated by whichever model is loaded, in both the streamed and the whole-answer mode.
